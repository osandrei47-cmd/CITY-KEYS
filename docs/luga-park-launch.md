# Запуск страницы «Луга Парк» (/proekty/luga-park)

Страница, компоненты, API и поля коллекций уже в коде. Ниже — что нужно
сделать руками, чтобы всё заработало на бою.

## 0. Схема БД

Добавлены поля:

- `Leads.interestType` (select: personal / investment) → колонка `leads.interest_type`
- `Listings.badge` (select: start / last) → колонка `listings.badge`
- `Listings.project` (одиночная relationship → projects) → **прямая** FK-колонка
  `listings.project_id` (не `listings_rels` — туда идут только hasMany/полиморфные
  связи, ср. существующий `listings.residential_complex_id`)

Все три — аддитивные (nullable), drizzle push применяет их без запроса и
без риска потери данных. Синхронизация:

```
# dev (city_keys_dev, из .env.local)
npx tsx scripts/sync-schema.ts

# боевая БД: положить web/.env.prod.local (прод DATABASE_URL + PAYLOAD_SECRET),
# затем тот же скрипт — он сам предпочтёт .env.prod.local
npx tsx scripts/sync-schema.ts
```

Скрипт запускает Payload dev push (`pushDevSchema` — тот же механизм, что
`next dev` при старте; в проекте нет файлов миграций) и проверяет, что все
три колонки появились. `NODE_ENV` в шелле не должен быть `production`.

Локально типы уже перегенерированы (`npm run generate:types`).

## 1. Боевое подключение для сидов

`.env.local` указывает на `city_keys_dev`. Скрипты ниже пишут в
**боевую** БД, только если рядом лежит `.env.prod.local` с боевыми
`DATABASE_URL`, `PAYLOAD_SECRET`, `S3_*`. Файл в `.gitignore`.

```
web/.env.prod.local
```

Без этого файла скрипты пишут в dev и печатают предупреждение.

## 2. Карточка проекта

Сначала загрузите **отдельное** фото обложки «Луга Парка» через админку
(`/staff-x7k2/collections/media/create`). Затем:

```
npx tsx scripts/create-luga-park.ts <имя-файла-обложки-в-Media>
```

Создаёт запись в коллекции Projects (slug `luga-park`, опубликована) —
карточка в разделе /proekty рядом с «Усть-Луга. ИЖС». Эта же обложка
выводится в герое страницы /proekty/luga-park и в OG-картинке.

**Важно про обложку:** нельзя переиспользовать медиафайл другого проекта —
это один и тот же media ID, и замена файла в нём меняет обложку сразу у
всех ссылающихся (так «Луга Парк» и «Усть-Луга» какое-то время делили одно
фото). Скрипт проверяет это и отказывается. Если проект уже создан с чужой
обложкой — тот же вызов с новым именем файла **обновит** обложку и отвяжет
от чужого медиа.

## 3. Шесть лотов 1-й очереди

```
npx tsx scripts/create-luga-park-listings.ts
```

Создаёт 6 записей Listings (4× тип А, 2× тип Б), привязывает к проекту,
ставит бейдж «Старт продаж» на первый лот каждого типа. Идемпотентно —
повторный запуск не плодит дубли. Цена в каждом лоте — без электричества;
обе цены и оговорка про подключение уходят в описание.

После запуска карточки лотов на /proekty/luga-park начнут вести на
/katalog/obyekt/[id] (печать/PDF работают из коробки). Фото лотам можно
добавить позже в админке.

Статус лота («В наличии» / «Забронирован» / «Продан») и бейдж
редактируются в админке в самой записи Listings — без разработчика.

## 4. PDF-презентация (лид-гейт, блок 7)

```
npx tsx scripts/upload-luga-park-presentation.ts
```

Без аргумента заливает заглушку
`scripts/assets/luga-park-presentation-placeholder.pdf` в приватный ключ S3
`private/proekty/luga-park-presentation.pdf`. Когда будет финальная
презентация:

```
npx tsx scripts/upload-luga-park-presentation.ts /путь/к/luga-park.pdf
```

Форма блока 7 показывается всегда; пока файла в S3 нет — заявка всё равно
сохраняется, человеку обещают прислать презентацию отдельно.

## 4a. Галерея территории (блок 6)

Поле **Projects → «Галерея (фото территории)»** (`gallery`, hasMany upload).
Грузить фото туда: `/staff-x7k2` → Projects → «Луга Парк» → «Галерея» →
Upload / Choose. Порядок в блоке 6 = порядок в списке.

- Пока галерея пустая — в блоке 6 показываются 6 плейсхолдеров (как
  сейчас). Как только добавлено хоть одно фото — плейсхолдеры сменяются
  реальной сеткой с лайтбоксом, без переверстки.
- Видео-обзор: положить файл в S3 по пути
  `videos/proekty/luga-park/presentation.mp4` (бакет `city-keys-media`) —
  плеер в блоке 6 появится сам (HEAD-проверка, `src/lib/luga-park-video.ts`),
  как у видео ЖК.

## 5. Что подтянется само

- **Навигация**: карточка в /proekty (после шага 2). Раздел «Проекты» в
  меню уже ведёт туда.
- **sitemap.xml**: slug добавлен в `HAND_BUILT_PROJECT_SLUGS`, попадёт в
  карту сайта, как только карточка проекта опубликована.
- **Каталог и фиды**: 6 лотов — обычные объекты `uchastki`, показываются
  в /katalog (категория «Земельные участки») и уходят в фиды
  Авито/ЦИАН/Яндекс/Домклик (per-lot чекбоксы «Публиковать на …» по
  умолчанию включены).
